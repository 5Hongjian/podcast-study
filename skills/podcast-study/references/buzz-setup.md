# 首次安装 Buzz、下载本地模型与转录

仅在文本获取阶段已经记录“无法获取完整可用字幕”或“需要补录部分缺段”时读取。本文件为新用户提供真实的准备流程，不要求每次转录重新安装。

## 1. 识别本机与已有能力

通过当前允许的系统工具确认操作系统、芯片架构、可用内存/磁盘空间，以及 Buzz 是否已经安装。不能把作者的 Apple 芯片 Mac 配置复制给所有用户。检查 Buzz 中已有模型和可用后端；必要时查看模型设置与实际文件位置，不全盘扫描私人目录。

明确三个可能状态：应用和模型均可用；只有应用可用；应用也缺失。只补齐缺少的部分。已有完整字幕时不会进入本步骤。

## 2. 下载与安装缺失的 Buzz

先查当次官方资料，再选匹配系统和架构的可用稳定版本：

- [Buzz 官方项目](https://github.com/chidiwilliams/buzz)
- [官方安装说明](https://chidiwilliams.github.io/buzz/docs/installation)
- [官方说明链接的安装包来源](https://sourceforge.net/projects/buzz-captions/files/)

macOS、Windows 和 Linux 的具体包及支持范围以运行时官方说明为准，不在技能中固定“最新版本”或猜包名。兼容旧架构时核对最后支持的版本；不要绕过限制强装不兼容包，也不要把同名其他软件当作此 Buzz。

简要告知用户此次需要安装的组件与实际可得的下载大小，按当前授权与系统权限要求继续下载、安装和首次启动。不要因技能而额外反复确认已授权的安装；若系统要求用户操作或安装授权确实缺失，只请求完成该必要步骤。不能代输管理员凭据或关闭系统整体安全机制。

下载完成核对包来源、大小与官方提供的校验信息（若有），确认可正常启动后记录实际版本和路径。授权/网络受阻就保存进度并说明，不把“已下载”写成“已安装”。这份技能的创建不意味着现在下载软件。

## 3. 获取合适的本地模型

优先复用适合节目语言的已有模型。缺少时使用 Buzz 的模型管理界面下载一个与其后端兼容的多语言模型；中文或混合语言不选仅英语模型。选择时根据实际硬件、资源与质量需求权衡，不默认下载最大模型，也不为了选型把所有模型下载一遍。

模型管理可参考 [官方模型设置](https://chidiwilliams.github.io/buzz/docs/preferences#model-preferences)。优先用应用支持的模型下载；自定义模型须由官方文档链接到的可信模型发布页确认格式与来源。不要将第三方镜像设为默认或改动全局下载配置。

本地转录后端与云 API 后端要明确区分；此流程默认 Buzz＋本地模型，不因缺模型改用付费云转录，不要求用户提供转录 API key。告知新用户模型会保留供后续复用，属于长期组件，不列入每期废纸篓清单。

下载结束确认模型能加载。取本次节目短片段试转，检查语言、识别质量与速度，再转录所需范围。若资源不足，选更小兼容模型或降低并行；最多做两次有根据的调整，仍失败就记录阻碍，不反复重转整期。

## 4. 执行与恢复

优先使用当前安装版本实际支持的 CLI；先检查可执行路径、版本与帮助，按 [官方 CLI](https://chidiwilliams.github.io/buzz/docs/cli) 组装参数。若桌面安装没有可用 CLI，则通过当前允许的应用控制操作 Buzz，不为了自动化重装另一套应用。没有本机执行/控制能力时，说明需要本机运行，不假装在云环境控制用户电脑。

选择转录而非翻译，保留原语言；导出可读取的文本与带时间格式（TXT＋SRT，或等价组合）。不要只依赖自动命名猜路径：记录实际导出名称，既可能在音频旁，也可能在应用配置的目录。

记录进程/任务标识、模型、后端、输入媒体版本与输出路径。恢复先检查实际运行与文件状态。文件存在但仍在写入、字幕只覆盖开头，不能作为完成证据。

后台检查使用当前可用的任务机制；如需调度，依用户的继续工作意图与运行时规则创建/更新对应跟进，完成后停止。只在完成、异常或需要用户操作时通知。应用与模型安装流程可恢复，不把聊天仍打开当作任务一定在运行。

## 5. 收尾归属

长期保留：Buzz、选定的本地模型、环境配置。

本次临时：下载的节目音频、试转片段、TXT/SRT/VTT、修订转录与临时副本。文档完成核验后才进入废纸篓；安装包是否清理由用户偏好另行决定，不扩大当前音频/转录清理范围。

以上链接用于执行时核对官方变化；安装版本、内存与下载大小必须以当次查询为准。
