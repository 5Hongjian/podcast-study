# 每期任务记录与恢复

启动或恢复时读取。状态根目录由 SKILL.md 的规则解析；其 `runs/` 只存当前用户的精简任务元数据，`sources/<run-id>/` 存完整结构化文字稿、内容与评估及引用依据；当前可写工作区的 `podcast-work/<run-id>/` 存原始导出稿与临时素材。按版本保存可恢复的发布包，正式资料也可放已确认的持久位置，记录实际路径，不能只存临时工作区。上述目录都在技能仓库之外；不要提交到 GitHub。仓库仅分发空白模板，没有任何人的真实单期记录。

## 创建与检索

先用已确认平台单集 ID 或规范节目 URL 在现有记录中检索，再回退到标题/嘉宾/集数核对。没有来源 ID 时使用随机运行 ID，不把模糊标题当成唯一身份。不同平台版本记录为同一单集的不同 `media_sources`，时间戳分别管理。

从 [运行记录模板](../assets/run-template.json) 创建 `runs/<run-id>.json`。模板中的 null 与空集合表示未获取，不表示通过；填写后才能保存为实际运行。具体时间使用实际系统时间，不复制模板或历史任务的时间。

新运行记录当前技能版本、工作流版本，内容与页面采用随附固定规范。不记录个人偏好配置；历史记录中已存在的旧配置字段保留但不参与新运行。不要把身份资料复制进单期记录。模板不再重复保存主题索引、输入/底稿/成品通过状态和内容指纹；历史记录中的这些字段保留但不能作为继续执行的依据，不自动迁移或改写。新字段保持可选以兼容旧记录；遇到不能理解的较新 schema 时保留原文件并说明限制，不能静默覆盖。模板升级不修改已存在的记录。

单个运行文件保存进度、产物位置和实际操作回执；质量结论以绑定当前产物的检查与评估为准。保存前读回、检查 `record_revision` 并递增。先写同目录临时文件再原子替换，避免半份 JSON；并发写同一期时串行协调，不仅依赖最后写入获胜。文件路径应是实际观察到的绝对路径。不要保存密码、访问令牌、全量字幕或模型私有推理。

## 状态与阶段

`status`：`running`、`waiting`、`needs_input`、`failed`、`site_verified`、`cleanup_pending`、`completed`。旧任务迁移使用 `historical_completed`，不能当成本版验证样例。

`stage`：`identify` → `captions` → `local_setup`（条件步骤）→ `transcribe`（条件步骤）→ `input_qa` → `content` → `review` → `publish` → `verify` → `cleanup` → `done`。

每个阶段记录 `pending/running/done/skipped/failed`、简短结果和可复用产物位置；不适用步骤标 `skipped`，不能伪造执行完成。

网站核验通过即交付网址；归档确认与清理随后继续，不阻塞用户阅读。`site_verified` 表示已完成网站核验，`cleanup_pending` 只表示清理尚未完成，不能撤回已核验的网站交付，也不能用网站完成代替清理完成。

用户明确只要本地阅读包时，final ready 且文件读回一致即完成该范围；网站发布与页面检查记为 not_applicable，不设置 site_verified，不虚构网站地址。发布能力暂时缺失而用户仍要求网站交付时，只保留进度，不能套用此例外称任务完成。

## 核验字段

`input_review` 按 [文字稿检查规则](input-quality.md) 记录身份、覆盖、忠实度、时间检查的状态、依据与问题；绑定 `source_version_id`、`transcript_sha256`、`media_duration_seconds`（未知为 null）。没有依据的 `passed` 无效，缺字段不视为通过。`transcript` 只记录原始导出稿、完整结构化稿的路径和来源身份，不把全文写进运行日志；原始导出稿清理后按文件清单记录真实状态，不能仍称原路径可读。继续时读取实际源包的 `qa` 及其绑定的输入评估，不手工复制 `readiness` 或覆盖检查状态。源包须来自已验收的版本归档，身份、原始哈希和时长与输入评估一致；存在变化或依据不明时回到输入核验。

`blocked` / `needs_review` 不进入 `content`；最多两轮局部修复后仍未解决则记录 `needs_input` 或具体失败，保留材料。`ready_with_limitations` 必须记录限制及其是否满足本次用途；例如无精确时间允许按原文定位，但不能交付未验证的精确回听。输入改动后旧检查失效，重新核验当前文件；历史已完成记录不为升级补做或倒填通过。

`checks` 只记录无法由内容检查报告推导的网站读回、导图呈现、链接、版式和笔记保存核验。状态用 `pending/passed/failed/not_applicable/unavailable`，同时记录必要原因与实际检查范围。

`content` 记录底稿、评估文件、检查报告的路径及修订轮数。主题与层级直接读取底稿 `nodes`，不另维护 `topic_index`。每次准备继续生成或发布，针对当前源包、内容与评估文件重跑现有 `check_content.py` 的相应阶段，读取本次结果；保存的旧报告只能供追溯，不能单独放行。这样重新计算实际指纹并核对评估绑定，无需重复进行仍有效的语义评审。失效范围以 [内容契约与评价标准](content-quality.md) 为准；禁止仅替换哈希来沿用通过。`site` 记录网站地址、部署版本及实际核验时间。旧任务没有这些可选字段时不能倒填通过。

硬性前提是所选目标已写完并核验，且无未解决的重要内容/导航错误。网站须分别记录内容检查和页面检查，确认当前版本与引用、笔记保存。确实不支持的播放器精确跳转要验证并交付已说明的节目链接＋时间替代；工具无法渲染页面不能写为视觉检查通过。是否允许带已说明限制交付，由当次任务要求决定，不能用“unavailable”掩盖必须修复的缺陷。

`site_verified` 必须有 `site.url/revision_id` 和实际页面核验，不能仅凭写入响应。字幕获取访问失败不等于 `unavailable`，保留失败原因。

## 文件与清理

只有网站核验完成，发布包包含全部原文段落、来源绑定和引用，且该期结构化全文、内容包、通过评估及已有个人标注已经持久保存并可读，确认能恢复同一发布版本后，才设置 `cleanup.eligible=true`。文件清单记录归档位置、版本及核验结果；不能只凭当前页面能打开就清理唯一全文。存在未解决的重要内容或导航错误时保留相关材料。

每个文件记录：路径、用途、是否本次生成/下载、`retention`（`durable` / `temporary`）、是否可清理、大小（若知道）、状态及实际废纸篓结果。完整结构化文字稿、必要修订/评估记录、内容/发布包、引用映射和个人笔记标为 `durable`，不可清理唯一副本。本次 TXT/SRT/VTT 原始导出稿在上述归档及网站核验完成、且不再承担唯一核验依据后可标为可清理；无需仅为网页显示保留重复文件。底稿中的冗余副本同样只在引用不再依赖它、长期副本已验证后清理。旧记录缺少保留类别时先查明用途，不默认可删除。不要把目录本身笼统加入删除清单；不列入模型、应用或用户原有唯一素材。

按单集及来源版本保留归档，不能只有会被下一期替换的 active `episode.json`。清理前比对归档与发布包的全文段落、顺序、稳定 ID、来源版本、原始指纹和引用范围，并验证无需原始导出稿也能恢复相同发布包。恢复可直接使用已保存的完整发布包，或通过归档结构化稿、内容包和有效评估重建；已有笔记仍依赖相同来源版本、哈希和段落位置。

网页全文完整不表示能恢复原始 TXT/SRT/VTT 的字节封装。清理原始导出稿后，旧哈希保留作来源身份，不能把拼接出来的新文件冒充旧文件复用输入评估；需要重新做原始文件级验收时，重新获取原文件或对重建文件按新版本验收。

清理前重新核对准确路径、归属、保留类别与完成状态，不扫描整个电脑按扩展名删除。移动时使用系统废纸篓机制，不用永久删除命令或清空废纸篓；确认原位置已移出并记录工具返回的目的地或回执。移动失败不把文件标记为 trashed，状态转 `cleanup_pending`。不清理其他任务文件、应用、可复用模型、凭证、用户原有唯一素材，以及仍承担唯一核验依据或未解决问题的文件。

## 恢复规则

- 转录还在运行：等待现有任务；已经完成：读取现有结果。
- 网站发布不明确：检查目标版本与部署状态，禁止盲目重复创建。
- 网站核验完成：即可提供已核验网址；清理未完成或失败时只处理清理，不重复内容生成、发布或整套页面检查。
- 用户只要求改笔记：从现有网站记录和相关来源开始，不自动下载或转录整期。
- 用户提交已完成单集且无更新要求：提供已有结果并说明，不无条件重跑。
- 更新需要原文：先读按版本保留的完整结构化稿与有效评估，或恢复该期发布包；本地导出稿已清理时不重新下载也可阅读、定位和恢复发布。需要原始字节级重验时，先确认废纸篓或原来源能否恢复；重建文件按新版本验收。旧任务未保留可用全文时再走字幕优先获取，不假装原文仍在本地。更换稿件版本不得把旧标注静默贴到新位置。

历史记录只标明有证据的已完成动作与已知限制，不倒填完整字幕查找、安装核验、独立审阅或 v2 导图检查。
