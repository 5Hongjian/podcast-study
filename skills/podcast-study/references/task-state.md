# 每期任务记录与恢复

启动或恢复时读取。状态根目录由 SKILL.md 的规则解析；其 `runs/` 只存当前用户的精简任务元数据，`preferences.md` 存个人偏好，`document-format.md` 存文档结构覆盖，当前可写工作区的 `podcast-work/<run-id>/` 存临时素材。状态目录放在技能仓库之外；不要提交到 GitHub。仓库仅分发空白模板，没有任何人的真实单期记录。

## 创建与检索

先用已确认平台单集 ID 或规范节目 URL 在现有记录中检索，再回退到标题/嘉宾/集数核对。没有来源 ID 时使用随机运行 ID，不把模糊标题当成唯一身份。不同平台版本记录为同一单集的不同 `media_sources`，时间戳分别管理。

从 [运行记录模板](../assets/run-template.json) 创建 `runs/<run-id>.json`。模板中的 null 与空集合表示未获取，不表示通过；填写后才能保存为实际运行。具体时间使用实际系统时间，不复制模板或历史任务的时间。

新运行记录当前技能版本、工作流版本，以及本次采用的配置来源和简短覆盖说明。不要把身份资料或完整偏好文件复制进单期记录。新字段保持可选以兼容旧记录；遇到不能理解的较新 schema 时保留原文件并说明限制，不能静默覆盖。模板升级不修改已存在的记录。

单个运行文件作为事实来源，保存前读回、检查 `record_revision` 并递增。先写同目录临时文件再原子替换，避免半份 JSON；并发写同一期时串行协调，不仅依赖最后写入获胜。文件路径应是实际观察到的绝对路径。不要保存密码、访问令牌、全量字幕或模型私有推理。

## 状态与阶段

`status`：`running`、`waiting`、`needs_input`、`failed`、`document_verified`、`cleanup_pending`、`completed`。旧任务迁移使用 `historical_completed`，不能当成本版验证样例。

`stage`：`identify` → `captions` → `local_setup`（条件步骤）→ `transcribe`（条件步骤）→ `input_qa` → `content` → `review` → `publish` → `verify` → `cleanup` → `done`。

每个阶段记录 `pending/running/done/skipped/failed`、简短结果和可复用产物位置；不适用步骤标 `skipped`，不能伪造执行完成。

## 核验字段

`checks` 分开记录输入覆盖、内容审阅、Docs 读回、导图呈现、链接核验和版式。状态用 `pending/passed/failed/not_applicable/unavailable`，同时记录必要原因。

硬性前提是目标 Docs 已写完并读回确认，且无未解决的重要内容/导航错误。确实不支持的播放器精确跳转要验证并交付已说明的节目链接＋时间替代；工具无法渲染页面不能写为视觉检查通过。是否允许带已说明限制交付，由当次任务要求决定，不能用“unavailable”掩盖必须修复的缺陷。

`document_verified` 必须有 `document.id/url` 和实际读回结果，不能仅凭写入响应。只有核验完成才设置 `cleanup.eligible=true`。字幕获取访问失败不等于 `unavailable`，保留失败原因。

## 文件与清理

每个文件记录：路径、用途、是否本次生成/下载、是否可清理、大小（若知道）、状态及实际废纸篓结果。不要把目录本身笼统加入删除清单；不列入模型、应用或原有素材。底稿中复制的转录也属于临时副本。

清理前重新核对归属与完成状态。移动时使用系统废纸篓机制，不用永久删除命令；确认原位置已移出并记录工具返回的目的地或回执。移动失败不把文件标记为 trashed，状态转 `cleanup_pending`。

## 恢复规则

- 转录还在运行：等待现有任务；已经完成：读取现有结果。
- 文档写入不明确：读取目标文档确认，禁止盲目重复追加。
- 文档完成、清理失败：只处理清理。
- 用户只要求改笔记：从现有 Docs 和相关来源开始，不自动下载或转录整期。
- 用户提交已完成单集且无更新要求：提供已有结果并说明，不无条件重跑。
- 临时材料已经清理而更新需要原文：先确认废纸篓仍可恢复；否则走字幕优先获取，不假装原文仍在本地。

历史记录只标明有证据的已完成动作与已知限制，不倒填完整字幕查找、安装核验、独立审阅或 v2 导图检查。
