# 文档结构与写作标准

这是可编辑的默认结构。每次生成或更新笔记时读取，再应用状态根目录的 `preferences.md`、`document-format.md` 及本次用户要求。用户可更改顺序、章节、详略和导图形式；下列顺序只在用户未覆盖时生效。长期修改写入本地覆盖文件，避免技能升级时丢失。事实忠实、出处和清理前核验仍遵循任务要求及主流程。

## 阅读顺序

### 1. 个人 takeaway

标题后直接进入对个人有用的启示，通常 3—5 条，但不凑数。每条写清“意味着什么 → 为什么与我有关 → 可执行动作”，并能追溯本期具体论点。仅使用用户明确提供且与当前任务有关的背景，不推测身份、职业或处境。

不要在开头放发布日期、整理日期、处理工具、冗长元数据或版本记录。必要的节目名、集数、嘉宾可作为简短副标题。

### 2. 一句话主线、思维导图与回听导航

先用一句话回答全期在解决什么问题。以这个问题为中心组织主要主题，用结论或问题短句命名节点，避免只有“AI”“战略”等名词。

节点编号与正文关键问题一致。每个重点节点有“看解释”链接和“听原话”时间/链接：前者使用已创建且验证过的文档标题定位，后者使用播放器实际支持的时间定位格式。一个主题可关联多个片段。为论证保留上下文，不只定位一句金句。

从带出处内容底稿生成导图结构与跳转映射，渲染后检查中文、字号与层级。如果 Docs 无法提供节点独立点击，使用“导图＋紧邻的同编号链接表”；明确这种呈现差异。播放器不支持定位时，给节目链接与真实时间，不拼接猜测参数。对应音频/视频不同版本的时间轴必须分别验证。

### 3. 把关键问题讲明白

每节：直接回答 → 推理过程 → 案例/白话解释 → 适用条件及个人用法（按内容需要选择）。问题数量随节目变化，不强制七个。

至少解释观点之间的因果、前提或区别。若一段只把原结论换个措辞，需回到来源补足“为什么”。优先使用节目原有案例；新增理解示例明确标注“整理者示例”，不能归给嘉宾。预测保持预测语气，不从类比推出确定赢家或时间表。

### 4. 来源与必要说明

保留节目链接、确有必要的外部核验和影响理解的输入疑点。外部核验只针对必要事实，不将每期自动扩成研究报告。主线、导图和正文不另行复制整套重复摘要。

## 内部底稿

底稿仅在本次任务期间使用。每条记录可含：`topic_id`、问题、回答、论证、原节目案例、限制、出处片段编号、开始/结束秒数、来源版本；补充示例与个人推导分别标识。它是写作资料，不自动新增用户文档章节或要求用户审阅。

## 审阅标准

- 忠实：观点、案例、数字和归属有原文依据；外部补充明确。
- 理解：关键术语有必要解释，推理没有被压缩成空泛结论。
- 关联：takeaway 来自本期，三个呈现共享同一依据。
- 导航：目标版本、时间与实际主题对应，链接真实可用。
- 可读：段落有主次，标题可扫描，导图能阅读而非仅装饰。

先解决内容问题，再处理局部排版。发现输入缺段要回到输入阶段；发现错链只修导航；避免因小修补重复生成全篇。
