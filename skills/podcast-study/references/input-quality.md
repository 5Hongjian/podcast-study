# 正确文本的获取与验收

本阶段交付可追溯的正式文字稿及其检查结果，再进入总结、导图和问答。完整原生文本优先；不因缺时间戳而重新转录全期。简介、精选、编辑摘要不能直接当逐字稿。访问失败与确定没有全文分别记录。

## 固定执行与判断分工

- 已支持渠道的读取、下载重试、转录参数、分段清单、结果合并与局部重跑使用已验证的固定工具或代码；记录实际采用的来源、模型和参数，复用已验收结果。当前随附脚本只负责已有文本的解析、检查与证据门禁，不提供下载器或转录服务。
- Agent 处理候选节目识别、替代官方来源及异常判断。换平台先确认是否为同一剪辑版本，不猜全期偏移；已确认有缺段时优先补缺段。
- 音频可得时，使用实际工具检查解码结果、实际时长、计划分段及各段完成状态。语音检测发现的空白、重复和时间覆盖只是待核验信号，不证明漏字、幻觉或全文完整。
- 输入评审使用单独的调用或审阅上下文；环境支持时可交给 eval agent。向它提供原始来源/音频及前后文、候选文字稿、脚本诊断与检查范围，避免直接采纳生成者的自我评分。生成者自称“完整、无幻觉”不算证据。无法独立调用或缺少音频核验工具时，记录实际审阅方式及限制，不补假通过；无需引入新的 Agent 运行时或调度器。
- 评审拿到原文、对应音频及前后文、异常位置和来源信息后，才可核验忠实度。只读文本的评审只能找疑点；不能以通顺、两个转录一致或外部事实纠正替代录音证据。嘉宾说错的事实也应忠实保留。
- 问题只修对应来源、片段或时间映射；有理由的局部修复最多两轮。仍有关键缺段或含义错误，保留稿件、证据与阻塞原因，不反复重跑全期，不进入完整内容生成。

## 随附检查脚本

从技能目录执行；实际资料与产物放在任务目录，不放进技能源码仓库：

```bash
python3 scripts/check_transcript.py /path/to/transcript.srt \
  --source-version media-v1 --kind asr --duration 7200 \
  --output /path/to/transcript-package.json
```

首次通常返回 `needs_review`。对照真实证据填好本期记录的 `input_review` 后再运行，增加 `--review /path/to/run.json`；也可传只包含评审对象的 JSON。不要复制合成测试里的“通过”结果。

支持 UTF-8 的 SRT、VTT、TXT，以及 BOM、CRLF、多行字幕、普通 VTT 头信息和提示设置。不会猜 TXT 的说话人或时间，不调用模型，不改写原文；仅标准化 BOM 与换行。TXT 段落保留分隔符，字幕正文保留原始内容及标记。不能解析的块直接阻塞，不跳过后假装获得完整文字稿。

输出为 JSON：`source_version_id`、原始文件字节的 `transcript_sha256`、`kind`、`format`、`time_precision`（`cue` / `unavailable`）、`segments` 和 `qa`。每段有 `id`、`text`、`source_cue_id`、`start_seconds`、`end_seconds`；无时间时为 `null`。段 ID 由来源版本、原始哈希和段序号稳定生成；相同字节及来源再次运行不会变。文字稿修订后哈希与 ID 更新，旧标注必须重新对应原句，不能沿用旧审阅结果。

引用字符偏移采用 Python Unicode 码点，起点包含、终点不包含，基于该段 `text`（包含保留的 VTT 标记）。网页如清除标记展示，需维护展示文字到原文的映射；JavaScript 的 UTF-16 索引也须转换，避免 emoji 等内容定位错误。时间是字幕 cue 的边界，不冒充精确的论点转场或词级时间。

`--output` 可省略，JSON 始终输出到标准输出；指定输出时原子写入，拒绝覆盖文字稿或评审输入（包括符号链接和硬链接指向同一文件）。脚本不修改 run 记录。退出码：`0` 可继续（包括附限制），`1` 需复核，`2` 阻塞/输入错误。

## 评审记录契约

评审对象必须绑定实际 `source_version_id`、`transcript_sha256` 和 `media_duration_seconds`；缺失或不匹配即阻塞。时长已知时为有限正数且等于本次 `--duration`，未知时必须显式为 `null`，不能省略或使用布尔值。更改已知时长或从未知改为已知，都会使旧的覆盖/时间评审失效，必须按实际来源重新检查；不能只改字段继承“通过”。带时间的稿件如媒体时长未知，会保留无法检查时间上界和尾部覆盖的限制。评审 JSON 的重复键（包括冲突状态）及非有限数直接拒绝，不采用最后一个值覆盖。

`checks` 含以下四项，各项为 `{ "status": "pending", "evidence": null, "basis": null }`。状态只允许 `pending`、`passed`、`failed`、`unavailable`。`passed` 必须说明实际证据位置、检查范围和方法，`unavailable` 必须解释限制；不给没有执行过的检查补“通过”。

| 项目 | 检查问题 | 允许支撑 passed 的 basis |
|---|---|---|
| `identity` | 是否指定节目及媒体版本？ | `metadata`、`publisher_transcript`、`audio_review`、`human_reference` |
| `coverage` | 是否覆盖全文，缺段是否解决？ | `publisher_transcript`、`audio_review`、`human_reference` |
| `fidelity` | 否定词、数字、专名、说话归属等是否忠实？ | `audio`、`audio_review`、`human_reference` |
| `timing` | 时间是否属于当前版本、位置是否核验？ | `publisher_timestamps`、`alignment_review`、`audio`、`audio_review`、`human_reference` |

`publisher_transcript` 的完整性依据应为发布方全文及范围信息，不能只是网页标题。它会保留“未独立核验音频覆盖”的限制。`human_reference` 必须是可信的人工参考稿，并写明对照范围。抽样核验写明抽样，不能升级成全文核验；开头、中间、结尾及异常片段是检查入口，另抽查正常片段以发现漏报。`text_only`、`coherence`、单纯首尾时间覆盖均不能支撑忠实度或全文完整性的通过。

`issues` 为数组，每项：`id`、`type`、`severity`（`critical` / `warning`）、`status`（`open` / `resolved`）、`segment_ids`、`reason`、`evidence`。全来源问题可用空 `segment_ids`；其他 ID 必须存在于当前产物。resolved 必须有实际修复或确认的证据；未知状态、重复问题 ID 或失效段 ID 都阻塞。旧稿证据不能靠改哈希“迁移”为已核验，应重新检查受影响内容。

## 路由规则

| `qa.readiness` | 条件与后续动作 |
|---|---|
| `blocked` | 解析失败、非有限/倒退/越界时间、来源/哈希不匹配、评审格式错误，或身份/完整性明确失败。先修输入，不生成完整精读。 |
| `needs_review` | 关键证据未确认、无依据的通过、忠实度/时间检查失败、未解决 critical、空文本段。ASR / mixed 无法核验忠实度也保留此状态。对照来源局部复核。 |
| `ready_with_limitations` | 身份与完整性有依据，无关键未决问题，但原生全文无音频忠实度核验、缺时间、媒体时长未知、发布方覆盖未独立核验或仍有 warning。把限制传给下游；没有时间就用段落定位。 |
| `ready` | 结构检查通过且四项已记录检查满足要求，无关键未决问题；可进入后续生成。 |

重复字句、重复原始字幕编号、未覆盖时间区间只是诊断，可能来自自然重复、静音或编号重置。时间重叠也可能是同时说话，须有 timing 复核才能继续，不直接判成不可能。无时间的原生全文如有可信身份/覆盖证据，可以把 fidelity、timing 明确记为 unavailable 后附限制继续。

**脚本核对的是结构及已记录证据，不验证评审陈述的真实性，不声称听过音频；任何 ready 都不表示“全文零错误、零幻觉”。** 完整结构化原文和评审依据的长期保存、导出稿清理及原始字节恢复，统一遵循 [任务记录与清理规则](task-state.md)。本文回归测试使用合成文本，不能视为真实节目转录质量已验证。
